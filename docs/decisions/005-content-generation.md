# 决策 005：M4 内容补全的模型与校验策略

**状态**：待定，由使用者拍板
**影响范围**：功能点 81–87，以及依赖音标的 39（词条列表）、50/51（详情页）
**与写代码的模型无关**：DeepSeek 负责生成**代码**，本决策定的是生成**孩子每天要看的学习内容**的模型。两者不是一回事，不要混用同一套判断。

---

## 要生成什么

`db/schema.ts` 的 `word_details` 已经把字段留好了：

| 字段 | 内容 | 错了的后果 |
| --- | --- | --- |
| `phonetic` | 英式音标 | **最严重**：错误示范，孩子照着念错，且会与 M5 的评分打架 |
| `phrase` | 常见搭配 | 中等：学到不地道的说法 |
| `sentence` + `translation` | 例句与翻译 | 中等：语境错了会误导词义理解 |
| `rootHint` | 词根助记 | 较轻，但**编造词源**很常见，且孩子会当真 |

风险不是均匀的。音标必须最严，词根助记要么做准要么不做。

---

## 关键约束：音标无法用底库校验

我核对了 `data/gaokao-3500.json` 的字段：

```
word, letter, pos, meaning, senses, variants, inflections, homograph, alias, id
```

**没有音标。** 所以 PRD 功能点 85 的「底库交叉校验」只能覆盖**词性和释义**，
覆盖不到音标——而音标恰恰是错了后果最严重的那个。

这意味着音标需要一条独立的把关路径，三个选项：

| 选项 | 说明 | 代价 |
| --- | --- | --- |
| **抽样人工核对** | 生成后按字母段随机抽 5%，人工比对词典 | 3431 词抽 170 个，一次性投入几小时 |
| **双模型交叉** | 两个不同模型各生成一次，不一致的置 `needs_review` | 成本翻倍，但能自动定位可疑项 |
| **不生成音标** | 只做 TTS 示范音，界面上不展示 IPA | 零风险，但孩子看不到音标，且 PRD 5.5 的词条列表要用 |

我的倾向是**双模型交叉 + 对分歧项人工确认**：单用户产品总量才 3431 词，
一次生成的绝对成本很低，翻倍也仍然低；而它能把人工核对的量从「抽样 170 个」
压缩到「只看真正有分歧的几十个」，且不是抽样，是全覆盖。

---

## 选模型时看什么

按这个顺序，不要按「哪个模型更强」这种笼统印象：

1. **能不能稳定输出结构化 JSON**。要一次生成 3431 词，
   哪怕 1% 的格式错误也是 34 条要手工救。有 JSON 模式或函数调用的优先。
2. **英式音标的准确率**。先拿 20 个词做人工验收，
   建议挑这几类：`schedule`（英美读音不同）、`either`、`route`、`vase`、
   `advertisement`、`privacy`、`mobile`、`missile`——这些正是英美分歧最大的词，
   能直接看出模型是不是真的在按 en-GB 输出，还是嘴上说英式、实际给美式。
3. **中文释义的质量**。它要与底库的释义风格一致（简洁、分号分隔），
   不能生成一整段解释。
4. **批量调用的价格与并发限制**。3431 词 × 每词一次，
   要看限流会不会把「一次跑完」变成「跑三天」。
5. **是否支持缓存或批处理折扣**。提示词是固定的，能命中缓存就便宜很多。

**不要**因为「编码用的是 DeepSeek，内容也用 DeepSeek 顺手」就直接定。
代码的对错有测试兜底，内容的对错只有孩子会撞上。

## 校验策略（PRD 85–86 的落地）

```
生成 → 命中 3500 底库？
        ├─ 是 → 比对词性与释义
        │        ├─ 一致       → 直接入库
        │        └─ 分歧       → needs_review = true，进审核队列
        └─ 否 → 无法交叉校验，标记来源为「仅 AI 生成」
                 音标另走双模型交叉
```

要点：

- **分歧不等于 AI 错**。材料上的释义可能就是与底库不同的义项，
  所以是「进审核」而不是「按底库覆盖」。审核界面（功能点 18–22）是这条路径的出口，
  没有它，`needs_review` 写了也没人看得到。
- **`edited_by_user` 是硬边界**。用户改过的字段，重新生成时不覆盖。
  这是 AGENTS.md 约束 9，也是我们与竞品的核心差异：
  竞品用免责声明代替纠错能力，我们给纠错能力。

## 任务管理（功能点 87）

3431 词不可能在一个请求里跑完，需要：

- `import_jobs` 表复用为生成任务表（表已建好，零引用）
- 按词书分批，记录已完成的 `wordId` 游标
- 中断后从游标续跑，不重复计费
- 失败的词单独记录，可重试，不阻塞整批

这部分与选哪个模型无关，可以先做。
