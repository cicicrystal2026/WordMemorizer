# 决策 004：音素级发音评测方案

**状态**：待定，由使用者调研后拍板
**前置决策**：`002-pronunciation.md`（口音定为 en-GB，录音用完即弃）
**影响范围**：功能点 52–59（整个 M5）、64（战报薄弱音素）

---

## 先纠正一个我此前的判断

我在架构评审里说「没有音标就没有对齐基准，所以 M4 必须先于 M5」。**这一条不成立。**

商用发音评测 API 接收的是**参考文本**（就是单词本身），音素词典和 G2P 在厂商内部。
我们不需要先生成 IPA 才能拿到音素级评分。

因此：

- M4（内容补全）与 M5（发音）**可以并行**，不是串行
- 音标仍要做，但用途是**展示**和跟读前的示范，不是评分基准
- 只有「自建强制对齐」这条路才真的需要我们自己持有音素词典

---

## 三条技术路线

### 路线 A：浏览器自带 Web Speech API

**不可行，但要写清楚为什么**，免得以后有人觉得「免费的先试试」。

`SpeechRecognition` 返回的是转写文本加一个整体置信度。它的目标是**听懂说了什么**，
不是**评价说得准不准**。孩子把 `think` 念成 `sink`，它多半照样转写成 `think`
（语言模型会纠错），或者干脆返回 `sink`——两种结果都无法告诉我们
「/θ/ 发成了 /s/」。

另外它在 iOS Safari 上支持很差，而孩子大概率用手机。

**结论**：可以用来做「有没有开口」的检测，做不了纠音。不作为方案。

### 路线 B：云端发音评测服务（推荐）

主流服务都提供：整词/句子的准确度、流利度、完整度，以及**逐音素得分**。
候选：

| 服务 | 备注 |
| --- | --- |
| 腾讯云 智聆口语评测（SOE） | 国内节点；与备案生态一致；如果域名最终落在腾讯云，链路最短 |
| 讯飞 语音评测 | 国内老牌，英文单词/句子评测成熟 |
| Azure AI Speech · Pronunciation Assessment | 能力最全（含韵律评分），en-GB 支持明确；但国内直连不稳定 |

**注意：以上是候选清单，不是结论。** 我无法联网核实各家当前的能力与价格，
下面的核实清单就是为此准备的。

### 路线 C：自建强制对齐

wav2vec2 / Kaldi / MFA 做音素对齐，自己算偏差。
需要常驻 GPU 或至少长时间运行的 CPU 服务，与 Cloudflare Workers 的模型不兼容
（Worker 有 CPU 时间上限，跑不了这个）。

**结论**：单用户产品不值得。除非路线 B 全部不可用，否则不考虑。

## 调研时要问到的九件事

按重要性排序。前四条任何一条不满足，这家就可以排除：

1. **是否返回逐音素得分**，而不只是整词分数。要看返回样例里有没有音素数组。
2. **是否支持 en-GB**。只支持 en-US 的话，孩子按英式念反而会被判错——
   这会直接摧毁孩子对这个功能的信任。见决策 002。
3. **个人开发者能否开通**。有些服务要求企业实名或行业资质。
4. **单词级评测是否单独计费**。我们的场景是一次一个单词、时长 1–2 秒，
   如果按「每次调用」而不是按音频秒数计费，成本模型会完全不同。
5. **能否浏览器直传**。理想链路是：我方 Worker 只签发临时凭证，
   浏览器把音频直接传给厂商。让音频经过我们的 Worker 中转会撞上 CPU 时间限制，
   而且违背「录音用完即弃」——中转就意味着我们碰过这段音频。
   （这正是 PRD 功能点 54「临时令牌签发」的由来。）
6. **临时凭证的有效期和权限粒度**。签发的令牌不能是全权密钥。
7. **音频格式与采样率要求**。浏览器 `MediaRecorder` 默认出 webm/opus，
   若厂商只收 16k PCM wav，前端要多做一层转码，这是隐藏工作量。
8. **厂商侧是否留存音频、留存多久、能否关闭**。评测对象是未成年人语音，
   这一条要有明确答复，不能只看隐私政策的泛泛表述。
9. **有没有免费额度**。单用户产品的用量极小——每天 50 词、每词 1 次，
   一个月不到 1500 次调用，很可能落在免费额度内。

## 拿到答复后的判断顺序

1. 先按第 1、2、3 条筛掉不合格的
2. 剩下的按第 5 条（能否直传）排序——这一条决定架构，不只是成本
3. 同等条件下选国内节点：孩子念完一个词要等两秒才出分，这个功能就废了

## 定下来之后我要做的事

无论选哪家，这几步是共同的，可以在你调研期间先把结构准备好：

| 功能点 | 内容 |
| --- | --- |
| 54 | `POST /api/pron/token` 签发临时凭证，不落密钥到前端 |
| 55 | 跟读关的录音交互：`MediaRecorder` + 波形提示 + 重录 |
| 56 | 评分结果落 `pron_scores` 表（表已建好，零引用） |
| 57 | 逐音素标色展示——**配色要过 `validate_palette.js`**，见 AGENTS.md 约束 6 |
| 58 | 三次不过允许跳过：卡在一个音上会摧毁整节课的节奏 |
| 59 | 音频不落我方存储，评分结果落库后即丢 |

其中 54 和 59 是安全与隐私边界，由我做；55–58 可以出规格交给执行方。
