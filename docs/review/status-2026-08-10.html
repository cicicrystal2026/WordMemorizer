四、关键路径

剩下的 58 项不是平铺的待办清单，它们之间有硬依赖。排错顺序会让做完的东西返工。

链条一 · 发音（可与内容补全并行） 选定评测服务 → 临时令牌 + 录音上传 → 逐音素标色 → 战报薄弱音素
链条二 · 内容补全（详情页已就位，等模型选型） 词条详情页 → 选定生成模型 → 批量生成 + 断点续跑 → 底库交叉校验
链条三 · 图片导入 审核界面 → 多模态识别 → 圈注识别 → 重点词 → 异步任务 + R2 存原图
链条四 · 练习质量（无依赖，规格已写） 分级出题 · 答错重现 · 遮盖自测 · 结算分项
更正

发音不必等音标

我此前判断「没有音标就没有对齐基准，M4 必须先于 M5」。这一条不成立： 商用发音评测 API 接收的是参考文本，音素词典和 G2P 都在厂商内部。 因此链条一与链条二可以并行推进，音标的用途是展示与跟读示范，不是评分基准。 只有「自建强制对齐」那条路才真的需要我们自己持有音素词典——而那条路对单用户产品不划算。

链条三把审核放在识别之前，是因为识别一定会错。先有能改的界面，识别的错误才是可修复的； 顺序反过来，孩子看到的就是一堆改不了的错词——这正是竞品用免责声明搪塞的做法。 词条详情页已经把「能改」这件事做完了，审核界面要复用同一套编辑接口。

五、三个需要你拍板的外部条件

这三项写代码解决不了，且都在关键路径上。越早启动，后面越不堵。

阻塞小程序

ICP 备案

beadfable.com 在 Cloudflare Registrar，不是工信部认证的域名注册商，无法备案。 Web 端不受影响，但小程序上线必须备案。要走这条路，需在腾讯云或阿里云另购一个域名走个人备案， 周期通常两到三周，且期间需要邮寄核验材料。

阻塞 M4 与 M5

内容生成用哪个模型

音标、例句、搭配、词根助记要在运行时生成。这与写代码的 DeepSeek 是两回事—— 它生成的是孩子每天要看的学习内容，错一个音标就是错误示范。 需要先定模型，再定「命中 3500 底库时交叉校验、分歧置为待审核」的校验策略。

阻塞发音纠正

音素级评分怎么做

浏览器自带的 Web Speech API 只能给出整词的识别置信度，做不到「/θ/ 发成了 /s/」这种颗粒度。 真正的音素级评分需要云端服务。这是整个产品最贵也最有价值的一块， 要先确认可用的服务与成本，再决定 M5 的排期。
